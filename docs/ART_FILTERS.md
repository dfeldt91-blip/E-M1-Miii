# Art filters: how their parameters are built (E-M1 Mark III 1.6)

Per-filter numbers: [ART_FILTERS_DATA.md](ART_FILTERS_DATA.md) (generated by
`tools/art_filter_dump.py FIRMWARE.BIN docs/ART_FILTERS_DATA.md docs/art_filter_curves.png`;
the tool checks every table address against the code it came from). Tone curves:
[art_filter_curves.png](art_filter_curves.png). Nothing here is camera-tested.

## Identification

- Each art filter is a picture-mode code in the Picture Mode list (0x604bc4f4, 64-byte entries):
  0x64 Pop Art, 0x65 Soft Focus, 0x66 Pale & Light Color, 0x67 Light Tone, 0x68 Grainy Film,
  0x69 Pin Hole, 0x6a Diorama, 0x6b Cross Process, 0x6c Gentle Sepia, 0x6d Dramatic Tone,
  0x77 Key Line, 0x78 Watercolor, 0x79 Vintage, 0x7a Partial Color, 0x7b Bleach Bypass,
  0x7c Instant Film. Mapping from the menu: the Picture Mode option list (0x611aeddc) uses GUI
  values 0xGGVV (GG = art GUI index, VV = variant) and the 0x6f validator's alt list (0x604ae834)
  maps GUI index -> code; variant counts match (Pin Hole and Vintage have III, etc.).
- Image jobs carry the key **0x01VV00MM** at job +52 (MM = code, VV = variant 1/2/3). The firmware
  also handles codes 0x59-0x63 and 0x6e-0x76, which are not in the menu (other bodies or internal
  passes); they are left unnamed.
- Selection code: 0x60380000-0x603e6000 (image processing setup). Per-filter behaviour comes from
  compiler hash switches ({key, handler} tables, some on key - 4/8/11) and ~40 functions with
  explicit key compares. The CPU's custom `udf` opcodes are multiplies (e.g. the 3x3 matrix product
  0x603dbb3b, 8 fractional bits).

## Stages mapped

| Stage | Code | Output | Per-filter data | Confidence |
|---|---|---|---|---|
| Tone (contrast) curve | 0x603df05c, switch 0x603df193 (key-11) | pointer to a 256-point curve, output 0..1023 | 21 art curves 0x6050b306-0x6050eda2 | high: shapes match the looks |
| Colour parameters | 0x603dd0c3, switch 0x603dd128 | 2 x 6 s16 at request +100..+123 | 12-byte tables 0x6051b0da-0x6051b25e | layout high, meaning unknown |
| Colour matrix | 0x603dbf28 | 3x3 s16 (256 = 1.0) | Pop Art I/II only: 0x6051affc (about +6% saturation) | high |
| Coefficient record | 0x603de54d, switch 0x603de57d | 13 pointers; the first goes to request +16 | records 0x6053d17c-0x6053d350 | layout high, meaning unknown |
| Register record | switch 0x603d88b1 (key-8) | 100-byte packed record | 0x604f8ece / 8f32 / 8f96 / 91ee / 9252 | meaning unknown |
| Processing chain | switch 0x60384953 (key-11) | list of module entry points (12-byte slots) | extra modules per filter | layout high, module roles inferred |

### Tone curve

Normal picture modes: the Contrast setting (job +1796) plus a per-mode offset (0x6050fba8) gives
a step that picks the curve: -3 0x60509f06, -2 0x6050a106, -1 0x60509506, 0 0x60509106 (or the
identity 0x60508f06), +1 0x60509306, +2 0x6050a306; modes 4 and 8 use 0x6050a506..0x6050ad06
(-2..+2), mode 10 uses 0x60509d06.
Art filters skip that: the switch returns a fixed curve, so **the Contrast setting has no effect on
art filters**. Partial Color and Bleach Bypass II use the identity curve. Conditional ones: Grainy
Film (only for sub-mode 0x100), Key Line and Watercolor (special passes 0x501 / 0x601 get a flat
white table or identity), Instant Film (only in pass 0x0b00).

### Colour parameters (2 x 6)

Normal modes: A = 0 x 6, B = (-1, 8, 0, 0, 0, 0). Dramatic Tone clears all 12. Pop Art I has the
largest A (53, 76, 100, 56, -1, 48), Diorama next (48, 44, 64, 32, 28, 48), which fits a
saturation-type control, possibly per hue sector; not confirmed (the reader of request
+100..+123 is not found yet). Cross Process gets extra handling after this stage (0x603dd444).

### Processing chain

The chain builder fills 12-byte slots with module entry points. All filters share a long middle
section (0x603889b5 ... 0x60388dca); the filter-specific modules are at the start and end of
the list (see the data file): Key Line adds seven modules (line extraction), Watercolor four, Dramatic
Tone two (local contrast), Diorama two (blur), Grainy Film several (grain), Gentle Sepia, Vintage
and Bleach Bypass I run a short chain of their own. Module roles are inferred from the filter
names, not decoded.

## Not mapped yet

- Sharpness for art filters, the grain texture, vignette (Pop II / Pin Hole), the blur (Soft Focus /
  Diorama), Partial Color's hue selection beyond its coefficient records.
- Meaning of the 2 x 6 colour parameters, the coefficient blocks and the 100-byte records.

## What this allows

- **Contrast / gradation per filter**: replace or reshape that filter's 256-point curve (one
  table each, 512 bytes; shared tables: Diorama I/II, Pin Hole II/III, Dramatic I/II).
- **Saturation**: Pop Art via its matrix; other filters probably via colour parameter A
  (needs a camera test to confirm).
- Sharpness: stage not located yet.

## Art curves as Gradation options (tests 1.715, 1.716)

`tools/patch_art_gradation.py` (on 1.709): Gradation gets 19 more values (3..21 raw, GUI 4..22),
one per distinct art curve, in every picture mode. 1.715 boot-looped: its data was at 0x600e1000,
a boot RAM pool (docs/FINDINGS.md); 1.716 puts it at 0x600dc000. The curve selector hook at 0x603df14e returns
the art curve for those values. Menus show ASCII names after Low Key. Awaiting camera test.
Unknown until tested: whether the new raw values reach job +1797 unchanged, and whether the SCP
shows names or blank entries for them.

Camera 1.716: works (options listed, live view and photos use the art curve), labels blank.
1.717: labels from the camera's own art filter name strings (0x3c-0x45, 0xa75-0xa8a, 0xcde).

Camera 1.719: works. The SCP Gradation picker shows the art filter icons for the 19 new options
(the blank entries were that icon picker; tools/patch_art_gradation.py).

## Bleach Bypass II softening (tests 1.720, 1.721)

`tools/patch_bleach2.py`, both on 1.719. Bleach Bypass II's own extras: request +8 bit 28
(0x603ddb0d) and, for photos only, a replaced main slot {0x60385e18, 0x60385f31} plus a final
pass 0x603870db (live view uses {0x60383c69, 0x60385f5b} and no extra pass). 1.720 drops the bit,
1.721 drops the final pass. Also special: no-NR-type flag 0x603ce1a8 (shared with Grainy, Vintage II),
coefficient record 0x6053d31c, identity tone curve.

## White frame for picture modes (test 1.722)

1.720/1.721 (Bleach Bypass II) made no visible difference; dropped. 1.722 = 1.719 +
`patch_frame_white.py --no-white --layer0-white` (clean white border masks) +
`tools/patch_frame_switch.py`: the SCP Color Space item becomes a Frame on/off switch (setting 0x3c,
icons/labels changed, its colour-space effect removed), and the chain builder adds the Frame stage
for non-art jobs while it is on.
Camera 1.722: no frame; SCP item still "Color Space" with Off / "2f 1.0EV" (borrowed icon ids are
per picker). 1.723: instead of the chain flag, the snapshot's Art Effect read (property 0xf5d1 ->
job +26825) returns Frame (3) when no effect is set and the switch is on; SCP icons back to stock.
Camera 1.723: SCP shows sRGB / Adobe RGB, no frame. Cause: the picture-mode normalisation at
0x6147d3e8 clears the Art Effect after the snapshot. 1.724 writes Frame there when the switch is on.
Camera 1.724: no frame (on or off). 1.725 (--diag): switch on -> Grainy I tone curve in picture
modes (tests whether the switch reaches image processing) + 1.722's chain flag hook.
Camera 1.725: nothing (no curve change, no frame): the property read 0x6005fa9c(0x8bf1) does not
see the switch from image code. 1.726: all checks use the settings getter 0x602ca6a5(0x3c).
Camera 1.726: switch reaches image code (Grainy curve on), still no frame. Cause: chain dispatch
0x603816c5 sends picture modes to builder 0x60395eb9 (no art effects). 1.727: photo jobs go to the
art chain builder 0x60384438 while the switch is on (live view unchanged).
Camera 1.727: switch on (Adobe RGB) + Natural photo -> crash and reboot; switch off (sRGB): no crash.
The art chain builder cannot take picture-mode jobs as they are (some art-only setup missing). Do not

## SCP grid cell shows AUTO for art values (tests 1.729, 1.730)

Camera 1.729 (`--diag-cell`, stock Auto entry given the Pop Art I icon): Auto showed ART 1, the art
values still AUTO, and the picker reopens on the chosen curve. So the grid cell uses record 0x17's
icon lists but its value is not found by the icon lookup 0x60e08efa (value d0, list a1, count d1;
in blob B). The settings getter 0x602ca6a5 -> 0x602dbfba maps the 64-byte Gradation value
{sid 0x69 raw, auto flag 0x9f} through the extended validator, so the value should be 4..22.
1.730 (`--cell`): the lookup, for the two Gradation icon lists only, searches all 23 entries (in case
the grid passes the stock count 4); if the value is still not found it shows entry (value mod 23),
so the icon shown identifies the value passed.
Camera 1.730: still AUTO for every art value. With the hook, any call of 0x60e08efa with the Gradation
lists would have shown an icon, so for art values the grid never looks them up in these lists (it
must take a separate path, e.g. a range check before the lookup, that falls back to AUTO). Left as
is: the curves work, the cell just reads AUTO. `--cell` is not used in builds.

## Grain in colour (test 1.731)

Picture modes cannot take grain: the grain modules (0x60388169, 0x60388295, 0x60388384) are only
added by the art chain builder 0x60384438; the picture-mode builder 0x60398689 has none, and the
hidden SCP "Film Grain Effect" cell (record 0x3e) has no image code behind it. Grainy Film's mono
look comes only from its toning entry (hash 0x6053e67c, handler 0x603dfd4a = always grey).
`tools/patch_grainy_color.py` (1.731 = 1.728 + this) points Grainy Film II at the default handler
0x603dfdc7 (colour); `--both` also does Grainy Film I.
Camera 1.731: live view in colour, photo still mono. The photo pass 0x603dfe9f (pass 0x101) checks
`cmp 0x1010068 / 0x1020068` at 0x603dfef3 / 0x603dfefb and calls the toning lookup with the mono flag.
1.732 changes Grainy II's compare operand to 0x10f0068, so the photo pass clears toning (colour).
Camera 1.732: photo still mono. The default toning handler 0x603dfdc7 still returns a mono vector
when the caller's mono flag (job +1801 in the first caller 0x603dfe30) is set, which stills
apparently do for Grainy. 1.733 points Grainy II at 0x603dfe11 (no toning, ignores the flag), plus the
1.732 photo-pass change. If 1.733 is still mono, the grey comes from the grain chain itself.
Camera 1.733: photo still mono (live view colour). Toning is not the cause: with no toning and the
photo-pass call skipped, Grainy II photos are still grey, so the photo grain chain itself outputs
luminance only (modules 0x60388169 / 0x6038385b / 0x60388295 / 0x603880f0, art builder
0x603845c1-0x6038466e). Colour grain would need those modules changed; not pursued yet.

## Bleach Bypass II softening, third try (test 1.734)

0x603ce1a8 returns 0 for Grainy I/II, Vintage II and Bleach Bypass II (else 1, with ISO- and
mode-dependent exceptions); 0x6038bcc1 stores it at job +1862. Probably the fine-detail /
sharpening stage. 1.734 = 1.728 + `patch_bleach2.py --detail` (Bleach II gets 1 like other filters).
Camera 1.734: no change. Described as "desharpening to the extreme". 1.735 = 1.728 +
`patch_bleach2.py --params`: the per-pass parameter-set index 0x603e3d98 (hash 0x6053ea8c) gives
Bleach II 34 / 35 for its passes 0xa01 / 0xa02; its entry now goes to the default handler 0x603e3ef4.
